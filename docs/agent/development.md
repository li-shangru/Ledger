# Development and verification

Read this reference for environment setup, dependency changes, testing, code conventions, and local integration. The safety and authorization rules in `AGENTS.md` apply throughout.

For substantive implementation or synthetic developer investigation, start with the
[implementation Skill](skills/ledger-implement-ticket/SKILL.md). It discovers relevant
knowledge and binds a coordinator-owned adviser allocation before actual host dispatch through the [factory](factory/README.md).
Known-domain work may justify zero advisers while retaining source/check obligations and fresh independent review.
No owner financial query or import is routed through this developer workflow.

## Installation

Ledger 1.11.2 requires Python 3.14. Its local read and proposal-write servers use
the stable MCP Python SDK 2.2. For the portable core CLI and MCP installation:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install .
python -m pip check
```

Use `python -m pip install -e .` instead when developing core source. This resolves
core dependencies for the host platform; it does not install the complete test
or dashboard environment. Runtime databases and defaults must stay outside the
checkout; see [Getting started](../getting-started.md).

## Optional features and platform support

| Profile | Scope and platform boundary |
| --- | --- |
| Core | CLI, SQLite processing, and MCP. `pip install .` resolves host-compatible dependencies. PDF extraction also needs Poppler's `pdftotext` on `PATH`. |
| `analysis` | Adds Polars for optional Parquet export. `pip install '.[analysis]'` needs compatible Python 3.14 native wheels or a supported local build. It is unnecessary for normal SQLite imports and queries. |
| `ui` | Adds Streamlit and Plotly. The supported repository wrapper verifies the exact official Streamlit wheel's provenance. The current builder and full UI verification environment target macOS 26 arm64. A plain extras install alone does not satisfy that wrapper's verification. |
| `dev` | Adds tests, linters, packaging, auditing, and a local Playwright derivative. The canonical lock and derivative target macOS 26 arm64. A bare `pip install '.[dev]'` cannot resolve that derivative from a public index. |

The supported complete development setup below is for **macOS 26 arm64** with
Python 3.14 and Poppler installed. Select an absolute external wheel destination;
`/absolute/ledger-build/wheels` is a placeholder, not a required system path:

```bash
export LEDGER_WHEEL_DIR=/absolute/ledger-build/wheels
./scripts/build-downstream-wheels "$LEDGER_WHEEL_DIR"
.venv/bin/python -m pip install --no-index --no-deps \
  "$LEDGER_WHEEL_DIR/streamlit-1.66.1-py3-none-any.whl" \
  "$LEDGER_WHEEL_DIR/playwright-1.62.0+ledger.1-py3-none-macosx_26_0_arm64.whl"
.venv/bin/python -m pip install --find-links "$LEDGER_WHEEL_DIR" -r requirements.lock
.venv/bin/python -m pip install --no-deps --force-reinstall -e .
.venv/bin/python -m pip check
```

The wheel builder accepts its destination as the positional argument above or
through `LEDGER_WHEEL_DIR`. Keep it outside the checkout. Select an external
`TMPDIR` when routing bulk temporary build, test, and browser output. Never
relabel the macOS derivative for another target; a new target needs its own
native artifact, lock, and verification.

Repository wrappers bootstrap only the profile they need: `import-pdf-inbox` and
`audit-statements` use `core`; `rebuild-db` uses `analysis`; `run-app` uses `ui`;
`freeze-check` and `ui-smoke` use `full-dev`. A wrapper may install dependencies in
this checkout's `.venv` and build required wheels. It does not make an unsupported
platform supported or grant permission to modify global clients.

## Lockfiles
`requirements.lock` is the canonical tracked lockfile used for reproducible installs.
It is a local interpreter/platform-specific freeze (Python 3.14 on macOS 26 arm64),
not a portable resolver output. A different target needs an audited native Playwright
wheel and target-specific lock; never relabel the existing artifact. Refresh the
lock only in a disposable core development environment containing no private
adapter distributions or private dependencies. Freezing an adapter installation
could expose private package identities and does not describe the public lock.
After an intentional dependency change, regenerate it while normalizing the two
direct wheel URLs back to their exact package versions (official Streamlit and
local Playwright):

```bash
.venv/bin/python -m pip freeze --all --exclude-editable \
  | sed -E \
      -e 's#^playwright @ .*$#playwright==1.62.0+ledger.1#' \
      -e 's#^streamlit @ .*$#streamlit==1.66.1#' \
  | LC_ALL=C sort > requirements.lock
```

`uv.lock` is an ignored local artifact generated by `uv` and is **not** tracked in git — it exists
only on machines that use `uv` and should not be committed or relied on in CI.

## Testing
```bash
# Run all tests
.venv/bin/pytest

# Run with coverage
.venv/bin/pytest --cov=ledger --cov-report=html:/absolute/ledger-build/coverage

# Run generic CSV profile and installed adapter tests
.venv/bin/pytest tests/test_csv_profiles.py tests/test_import_adapters.py

# Run tests matching pattern
.venv/bin/pytest -k "money"

# Complete source verification without resolving the default financial database.
LEDGER_FREEZE_SYNTHETIC=1 LEDGER_FREEZE_SOURCE_ONLY=1 ./scripts/freeze-check
```

Synthetic and source-only modes are the public defaults. Synthetic mode creates and removes its own owner-only database, forwards that explicit
path to database and UI gates, and refuses `LEDGER_FREEZE_AUDIT=1`. A retained-source statement
audit is a distinct operator-selected-data gate and must never be inferred from synthetic proof.

For user-visible UI changes or complete source release proof, add
`LEDGER_FREEZE_UI=1` and an available explicit `PORT` to the source-only freeze
command. Keep the wheel directory and bulk test output external. This checks the
dashboard with a synthetic database; it does not inspect a private runtime or
synchronize client Skills.

The [GitHub source workflow](../../.github/workflows/ci.yml) runs this complete
synthetic UI gate and fresh MCP probes on macOS 26 arm64 for pushes and pull
requests to `main`. It installs the exact lock and verified downstream wheels,
uses temporary directories outside the checkout, and has read-only repository
permissions. It does not use a private financial runtime or configure clients.

## Code Quality

### Linting and Formatting
This project uses **Ruff** for both linting and formatting:
- Configuration in `pyproject.toml` under `[tool.ruff]` and `[tool.ruff.lint]`
- Pragmatic ignores for personal project:
  - `E501`: Line length handled by formatter
  - `RUF022`: Don't require sorted `__all__`
  - `RUF012`: Don't require ClassVar for class constants
  - `B904`: Don't require exception chaining
  - `SIM102`: Allow nested if statements
- `F401` (unused imports) is **not** a project-wide ignore; it is a per-file ignore
  scoped to `src/ledger/parsers/__init__.py`, which re-exports the generic parser
  API. Private adapters are loaded only through explicit installed-package pins;
  public parser imports do not register institution-specific modules.

**Important**: For SQLAlchemy boolean comparisons, use `== False` with `# noqa: E712` when needed:
```python
# Correct for SQLAlchemy
query.filter(TransactionDB.exclude_from_spending == False)  # noqa: E712

# Wrong - creates Python boolean, not SQLAlchemy expression
query.filter(not TransactionDB.exclude_from_spending)
```

### Type Checking
This project uses **pragmatic type checking** suitable for personal projects:
- `disallow_untyped_defs = false`: Allow untyped functions
- `disallow_incomplete_defs = false`: Allow incomplete annotations
- `check_untyped_defs = false`: Default config skips untyped bodies, but the freeze
  gate overrides it with `--check-untyped-defs`

This balances type safety with development speed for personal use.

## Completion and activation

For substantive work, record a concise plan and acceptance criteria, write the
independent review brief, complete relevant checks, and resolve validated review
findings. Small prose edits need a short approach and link/diff checks; follow the
project's required integration gates in either case. Make reasonable assumptions for reversible choices; ask the
operator only about a true blocker, essential target ambiguity, or ungranted side
effects. Preserve explicit read-only, branch-only, checkpoint, and no-install limits.

A normal contribution is complete at source verification. It does not require
reinstalling an existing client, inspecting saved client configuration, or copying
Skills into global directories. Report source, package, UI, and platform evidence
separately; do not call a source-only result installed delivery.

When the user explicitly requests installation into configured maintainer clients,
follow [Local delivery](delivery.md):

1. Run `./scripts/deliver` only within that authorized installation scope. It runs
   the synthetic UI gate, reinstalls editable metadata, synchronizes canonical
   Skills to configured client roots, and checks fresh read/write MCP processes.
2. Use `./scripts/delivery-check` for later installed freshness checks. To include
   it in a freeze run, explicitly set `LEDGER_FREEZE_SOURCE_ONLY=0`. The default
   source-only gate does not require or create an installed delivery receipt.
3. Existing MCP processes retain loaded code and instructions. Affected connections
   need a restart or new client session after delivery. Fresh synthetic processes
   prove availability; they do not prove that an existing connection adopted it.

The final handoff states what changed, independent review, exact checks, platform
limits, and any requested installation status. Do not claim a pending installation,
approval, UI check, or publication is complete.

## Distribution inputs

Use the configured PEP 517 backend through `pip wheel .` or a PEP 517 build frontend.
It admits tracked source files, builds from an immutable snapshot, and checks every
wheel or source-distribution member before returning the artifact. Untracked files
are excluded. Exported trees and source distributions carry `SOURCE_MANIFEST.json`;
changed declared files fail verification. Generic source ZIPs without that manifest
are not supported build inputs. Do not bypass this boundary with a direct Hatch CLI
build. Editable wheels refer to their local source directory and are development
artifacts, not release packages.

The source exporter is `python scripts/public_source.py`: use `check --repo` to get
the manifest digest, `export --repo --dest --expect-sha256` to copy the exact reviewed
files to a new external directory, and `verify --dest --expect-sha256` to compare
bytes, modes, and file inventory. Fill each option with its value; `--dest` must not
exist. This structural check does not replace review of fixture provenance.

Documentation images are limited to lowercase `.png` names directly under
`docs/images/`, using letters, digits, underscores or hyphens (at most 96 stem
characters, beginning with a letter or digit). Only noninterlaced 8-bit RGB is
admitted: at most 2 MiB, 4096 pixels per axis, 8 million pixels and 1024 chunks.
The validator checks CRCs, chunk order and bounded scanline decompression, allowing
only `IHDR`, consecutive `IDAT` chunks and a final `IEND`. Metadata and trailing
content are refused. Human review of the exact image pixels and their synthetic
provenance remains required before publication; structural validation cannot
certify privacy. Exports and source distributions preserve admitted images and
their manifest hashes. The wheel payload remains package code and bundled seeds.
